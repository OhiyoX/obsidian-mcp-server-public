# 部署时间显示功能

## 目标

在版本信息中显示**部署的精确时间**，要求前后台均展示，并满足：
1. **精确性**：同时提供本地时间（含时区偏移）与原始 ISO 格式（UTC，可机读）
2. **明确性**：部署时间未知时给明确文案，不留空白
3. **一致性**：前后台使用统一的格式化逻辑

## 数据契约

### 数据来源

使用现有 `app/src/release-version.js` 的 `deployedVersion()` 函数，返回：
```javascript
{
  version: string,      // 版本号，如 "0.9.12"
  commit: string|null,  // Git SHA，如 "ba79fc49" 或 null
  deployedAt: string|null, // 部署时间 ISO 字符串（UTC），如 "2026-10-10T04:40:07Z" 或 null
  source: "deploy"|"config" // 数据来源：manifest 或配置回退
}
```

数据源为 `<DATA_PATH>/deployed-version.json`，由 `scripts/nas_deploy.py` 在每次 apply/rollback 时写入。本地运行或 manifest 缺失时，`deployedAt` 为 `null`。

### 格式化契约

新增纯函数 `formatDeployTime(isoString)` 于 `release-version.js`：

**输入**：
- `isoString`: string|null - ISO 8601 格式的 UTC 时间字符串或 null

**输出**：
```javascript
{
  iso: string|null,    // 原始 ISO 字符串（UTC），如 "2026-10-10T04:40:07Z"
  local: string|null,  // 本地时间格式化字符串，如 "2026-10-10 12:40:07 +08:00"
  label: string        // 显示文案，未知时为 "未部署 (本地运行)"
}
```

**格式规范**：
- `local` 格式：`YYYY-MM-DD HH:mm:ss ±HH:MM`（使用运行时时区）
- `iso` 保持原样（UTC 格式，如 `2026-10-10T04:40:07Z`）
- 当 `isoString` 为 `null` 或无效时，`iso` 和 `local` 均为 `null`，`label` 为明确的未知文案

### 后台 API 字段扩展

在以下端点添加新字段（**只增不改**现有字段）：

#### 1. `GET /healthz`
**新增字段**：
- `commit`: string|null - Git commit SHA
- `deployedAt`: string|null - 部署时间 ISO 字符串
- `deployedAtFormatted`: object - 格式化后的部署时间
  ```javascript
  {
    iso: string|null,
    local: string|null,
    label: string
  }
  ```

#### 2. MCP `server_info` 工具
**新增字段**（同 `/healthz`）：
- `commit`: string|null
- `deployedAt`: string|null
- `deployedAtFormatted`: object

#### 3. `GET /`
**新增字段**：
- `deployedAtFormatted`: object（已有 `version`、`commit`、`deployedAt`，仅补格式化字段）

### 前台显示改进

#### 1. Admin 头部（`app/src/admin/auth-center.js:103-105`）
**当前**：`部署于 ${release.deployedAt}`（原样 ISO）

**改为**：
- 已知时：`部署于 2026-10-10 12:40:07 +08:00 (2026-10-10T04:40:07Z)`
- 未知时：`未部署 (本地运行)`

#### 2. 页面标题（`app/src/app/pages.js:95-96`）
**当前**：`部署于 ${release.deployedAt}`

**改为**（同 Admin 头部格式）

#### 3. UI Chrome `versionLabel()`（`app/src/release-version.js:54-58`）
保持现有 `version · commit` 格式不变（避免破坏既有测试），或可选添加短格式时间（需同步更新测试断言）。

## 验收判据

### 功能正确性
1. **后台 API**：
   - `GET /healthz` 返回包含 `commit`、`deployedAt`、`deployedAtFormatted` 字段
   - MCP `server_info` 返回包含 `commit`、`deployedAt`、`deployedAtFormatted` 字段
   - `GET /` 返回包含 `deployedAtFormatted` 字段
   - 格式化字段包含 `iso`、`local`、`label` 三个属性

2. **前台显示**：
   - Admin 头部显示本地时间 + ISO（已知时）或明确未知文案
   - 页面标题同样显示格式化后的时间
   - 未知时显示 "未部署 (本地运行)" 而非空白或原始 null

3. **格式化函数**：
   - 输入有效 ISO 字符串，返回正确的本地时间格式
   - 输入 null，返回 null 和明确文案
   - 输入无效字符串，返回 null 和明确文案（容错）

### 负控测试（至少 1 条）
1. **部署时间为 null**：
   - `formatDeployTime(null)` 应返回 `{ iso: null, local: null, label: "未部署 (本地运行)" }`
   - 前台显示应为 "未部署 (本地运行)"，不应为空白或 "undefined"
   - 后台 API 应返回 `deployedAt: null` 和对应的格式化字段

2. **无效 ISO 字符串**：
   - `formatDeployTime("invalid")` 应返回 null 值和明确文案，不应抛异常

3. **现有字段不变**：
   - 旧版 `version` 字段值保持不变
   - 已有的 `commit`、`deployedAt`（`GET /` 中）值和格式不变

### 回归测试
- 所有既有测试必须通过
- 如需修改既有断言，必须是因本次口径变更（如预期字段从 1 个变 4 个）
- `versionLabel()` 如保持不变，其测试必须原样通过

## 边界与约束

### 不改动项
1. **不改变现有字段语义**：
   - `version`、`commit`、`deployedAt`（ISO 字符串）的含义和格式保持不变
   - 只新增 `deployedAtFormatted` 字段

2. **不修改部署脚本**：
   - `scripts/nas_deploy.py` 的 manifest 写入格式不变
   - 如发现 `deployedAt` 未被写入，仅在 HANDOFF 报告，不擅自修改部署脚本

3. **不改变数据来源**：
   - 继续使用 `deployedVersion()` 作为唯一数据源
   - 不创建新的配置文件或环境变量

### 最小改动面
- 仅修改必要的文件和行
- 复用现有的 `deployedVersion()` 调用
- 格式化逻辑集中在一个纯函数中，便于测试和维护

## 实现注意事项

1. **时区处理**：使用 JavaScript 内置 `Date` 对象和 `Intl.DateTimeFormat` 或类似方法获取运行时时区
2. **容错性**：格式化函数必须处理 null 和无效输入，不抛异常
3. **纯函数**：`formatDeployTime()` 应为纯函数，便于单元测试
4. **一致性**：前后台使用同一个格式化函数，避免格式不一致
5. **文案明确**：未知时的文案应清晰表达含义，避免用户困惑
