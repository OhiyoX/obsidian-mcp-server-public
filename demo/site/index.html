Self-hosted · Markdown-native · MCP

自托管 · Markdown 原生 · MCP

Your notes are already the interface.

你的笔记，
本身就是界面。

One self-hosted Markdown vault that multiple agents can share — Claude, Cursor, Codex, or your own tools, from different machines and networks. They read and write the same knowledge and memory, with per-agent credentials and attributed writes.

一个自托管的 Markdown Vault，多个 Agent 共享——Claude、Cursor、Codex，或你自己的工具，来自不同机器和网络。它们读写同一份知识与记忆；每个 Agent 独立凭据，写入带归属。

It speaks Streamable HTTP MCP, returns a revision on every note write, and keeps memory and skills as plain Markdown you can open. The memory is one set of files, not one silo per agent.

它使用 Streamable HTTP MCP，每次笔记写入返回 revision，把记忆和 Skill 保持为可直接打开的 Markdown。记忆是一组文件，而不是每个 Agent 各一套孤岛。

One memory, many agents.

一份记忆，多个 Agent。

The point is not another chat client. It is a shared substrate: one self-hosted vault, reachable over HTTPS, where different agents on different machines read and write the same knowledge and memory.

重点不是再做一个聊天客户端，而是一层共享底座：一个自托管 Vault，通过 HTTPS 可达，让不同机器上的不同 Agent 读写同一份知识与记忆。

Not a sync product: one server and one vault, with many clients. Remote access is your network boundary — HTTPS, a VPN, or a private tunnel.

Same memory, no silo

同一份记忆，没有孤岛

Every connected agent calls the same memory_recall and reads the same files. A decision captured by one agent is available to the next, without an export step.

每个接入的 Agent 调用同一个 memory_recall，读同一批文件。一个 Agent 记下的决策，下一个 Agent 直接可用，不需要导出。

Per-agent credentials

每个 Agent 独立凭据

Give each agent its own OAuth account or API key, scoped to read, write or files and limited to chosen vaults. Revoke one without touching the others.

每个 Agent 使用独立的 OAuth 账户或 API Key，按 read / write / files 分权，并限制到指定 Vault。撤销一个不影响其他 Agent。

Attributed writes

写入带归属

Writes can carry an author and model trailer, and the admin audit records which agent acted. You can tell who changed what.

写入可带 author / model 归属，Admin 审计记录是哪个 Agent 操作。谁改了什么，可以追溯。

Conflict-safe by default

默认冲突安全

Every note write returns a revision. A stale write is rejected instead of silently overwriting another agent's change; multi-note plans are journaled.

每次笔记写入返回 revision。过期写入会被拒绝，不会静默覆盖另一个 Agent 的修改；多笔记计划写入 journal。

三个 Agent 的一天

09:10 Cursor 记录一条设计决策。14:30 另一台机器上的 Claude 召回它。22:00 脚本 Agent 更新项目 README。同一个 Vault、同一份记忆、不同凭据。

I

Workspace

工作区

Browse, read and edit the vault in the browser. Every document has a deterministic route; the explorer, properties and outline stay in reach.

在浏览器里浏览、阅读和编辑 Vault。每个文档有稳定路由，文件树、属性和大纲始终在手边。

Three view modes — reading, source and live preview — share the same document. Properties come from frontmatter and can be edited in place. Writes carry a revision, so a stale tab is rejected instead of silently overwriting a newer note.

阅读、源码、实时预览三种视图共享同一份文档。属性直接来自 frontmatter，可就地编辑。写入携带 revision，过期标签页会被拒绝，而不是静默覆盖新内容。

  • Explorer in tree or flat mode, with per-folder note creation.
  • Revision-aware writes that refuse stale editors.
  • Attachments and themes served from the vault itself.
  • 文件树支持树状/平铺，可按目录新建笔记。
  • 写入带 revision，过期编辑器会被拒绝。
  • 附件与主题直接从 Vault 提供。
II

Memory

记忆

Durable memory is a folder of typed Markdown: decisions, facts, episodes and preferences. Each note carries its kind, confidence, entities and project links, so recall can explain itself.

长期记忆是带类型的 Markdown：决策、事实、片段、偏好。每条都有 kind、置信度、实体和项目关联，召回结果可以解释。

Memory is managed under _Workspace/20-Memory, but it never restricts free-form notes elsewhere. Capture and recall are MCP tools; the underlying records stay ordinary files you can open, diff and link.

记忆统一放在 _Workspace/20-Memory，但不会限制 Vault 其他区域的自由笔记。捕获与召回是 MCP 工具；底层仍是可打开、可 diff、可链接的普通文件。

  • memory_capture for structured records; the agent contract forbids full transcripts.
  • memory_recall with lexical and optional semantic signals.
  • Typed frontmatter: kind, status, confidence, entities, projects.
  • memory_capture 只写结构化记录；Agent 契约禁止保存整段对话。
  • memory_recall 支持词法与可选语义信号。
  • 类型化 frontmatter：kind、status、confidence、entities、projects。

A decision you can read six months later is worth more than a vector you cannot inspect.

半年后还能读懂的决策，比一个无法检查的向量更有价值。

III

Skills

Skill

Skills are directory packages with a SKILL.md and optional references, scripts and assets. They are validated, matched and exported as files — matching never executes one.

Skill 是目录包：SKILL.md 加可选的 references、scripts、assets。可校验、可匹配、可打包导入导出；匹配到 Skill 不等于执行。

A skill declares its triggers, allowed tools, trust and risk. Validation checks names, metadata and package paths. Import and export use zip archives with path-traversal checks.

Skill 声明 triggers、allowed-tools、trust 与 risk。校验会检查命名、元数据和包路径；导入导出使用 zip，并做路径穿越检查。

  • Portable agent-skills package layout.
  • Validated before it is offered to a host.
  • No side effects: match returns executionAuthorized: false.
  • 可移植的 agent-skills 包结构。
  • 先校验再提供给宿主。
  • 无副作用：匹配返回 executionAuthorized: false。
IV

Search and reading

检索与阅读

Search runs an exact lexical pass first, with semantic recall as a fallback. Results carry snippets, match counts and reasons. The reader renders Markdown, KaTeX, Mermaid, tables and footnotes from the vault itself.

检索先精确匹配，语义召回只作为回退；结果带片段、命中数和原因。阅读视图直接从 Vault 渲染 Markdown、KaTeX、Mermaid、表格和脚注。

The ranking is explainable: each hit includes score, reasons, matchCount and the lines that matched. By default, semantic retrieval is optional and only escalates when the exact pass is empty.

排序是可解释的：每个命中都带 score、reasons、matchCount 和命中的原文行。默认情况下，语义检索是可选项，只在精确结果为空时升级。

  • Lexical-first for identifiers, paths, tags and aliases.
  • Hybrid fallback through an optional embedding service.
  • Local rendering for math and diagrams; no external CDN.
  • 先词法，适合标识符、路径、标签和别名。
  • 混合回退，可选接入 embedding 服务。
  • 本地渲染公式与图表，不依赖外部 CDN。
V

Bases

Bases

Bases stay in the vault as .base files. Filters, sort, views and a narrow formula subset are evaluated safely; unsupported expressions fail closed instead of running JavaScript.

.base 文件留在 Vault 里，支持筛选、排序、视图和受限公式子集；不支持的表达式直接拒绝，不执行任意 JavaScript。

Projects and memory become live tables without a second schema. The view definitions are versionable files, and the same query surface is available to agents through MCP.

项目与记忆不需要第二套 schema 就能变成实时表格。视图定义本身是可版本化的文件，Agent 也能通过 MCP 使用同一套查询面。

  • Project board filtered by tag, sorted by priority.
  • Memory index built from typed frontmatter.
  • Fail-closed on unknown filters and formulas.
  • 项目板按标签筛选、按优先级排序。
  • 记忆索引直接来自类型化 frontmatter。
  • Fail closed：未知筛选与公式直接拒绝。
VI

Publish

发布

Publish one note to a read-only page and revoke the link later. The source note is untouched, and the catalogue records vault, path and time.

把单篇笔记发布成只读页面，之后可以撤销链接；原笔记不受影响，目录记录 Vault、路径和时间。

This is a narrow sharing primitive, not a clone of Obsidian Publish. It is per document, independent of the official service, and manageable from both the workspace and the admin console.

它是窄范围的分享能力，不是 Obsidian Publish 的复制品。按文档发布、独立于官方服务，并可在工作区与 Admin 两侧管理。

  • Anonymous read-only public page.
  • Revocable without deleting the source.
  • Cross-vault catalogue with publication time.
  • 匿名只读公开页。
  • 可撤销，不删除原文。
  • 跨库发布目录记录发布时间。
VII

Several vaults

多 Vault

One server, several vaults. Agents select a vault per call with vaultId; the browser session switches vaults and keeps its own tree, search scope and allowlist.

一个服务器，多个 Vault。Agent 按调用传 vaultId，浏览器会话可以切换 Vault；文件树、搜索范围和账户白名单各自独立。

Each vault gets its own catalog and index. A search in one vault cannot cite another, and the admin allowlist decides which accounts see which vault at all.

每个 Vault 有独立的目录与索引：一个库里的搜索不会引用另一个库；账户能看到哪些 Vault 由 Admin 白名单决定。

  • Per-call scoping for agents working across projects.
  • Per-account allowlist enforced at session and admin layers.
  • Isolated catalogs so indexes never bleed.
  • 按调用指定，适合跨项目的 Agent。
  • 账户级白名单，在会话与 Admin 两层校验。
  • 目录隔离，索引不串库。
VIII

Theme

主题

Follow the desktop, follow the system, or force light or dark. Vault community themes are supported too.

跟随桌面端、跟随系统，或强制浅色/深色；也支持 Vault 的社区主题。

The same reading surface, at whatever contrast you need. The preference is saved per browser, and a vault’s own theme CSS can replace the default look.

同一个阅读界面，按你需要的对比度呈现。偏好保存在当前浏览器；Vault 自带的主题 CSS 可以替换默认外观。

  • Desktop / system / light / dark color modes.
  • Vault themes through standard Obsidian theme files.
  • Saved locally, not in the vault.
  • 桌面端 / 系统 / 浅色 / 深色四种模式。
  • Vault 主题兼容标准 Obsidian 主题文件。
  • 本地保存，不写入 Vault。
IX

Admin

管理

A separate admin surface with its own password: scoped API keys, OAuth accounts, dynamic clients, access and refresh grants, publish records and a secret-free audit log.

独立的管理面板，使用独立密码：带 scope 的 API Key、OAuth 账户、动态客户端、访问/刷新授权、发布目录，以及不含秘密值的审计日志。

Credentials are scoped to read, write and files, and bound to an explicit vault allowlist. The audit records the actor, credential type, source and outcome — never the credential value.

凭据按 read、write、files 分权，并绑定明确的 Vault 白名单。审计记录操作者、凭据类型、来源和结果，但不记录凭据值。

  • API keys with scopes and vault allowlists.
  • OAuth 2.1 + PKCE grants with rotation and revocation.
  • Audit with action, agent, source and outcome.
  • API Key 带 scope 与 Vault 白名单。
  • OAuth 2.1 + PKCE，支持轮换与撤销。
  • 审计记录动作、Agent、来源和结果。

Mobile

移动端

The shell collapses into a drawer without losing the tree, search, reader or editor. The same routes, auth and workspace on a phone.

移动端把文件树收进抽屉，但搜索、阅读、编辑和路由都保留；手机上是同一套认证与工作区。

It is not a stripped-down viewer. The full folder tree is in the drawer, and a web app manifest ships with the shell. Installable PWA support is still on the roadmap.

它不是删减版查看器：完整文件树在抽屉里；随应用提供 Web App Manifest，可安装 PWA 仍在路线图中。

  • Full tree in a touch drawer.
  • Same routes and auth as desktop.
  • Web app manifest; installable PWA is planned, not shipped.
  • 完整文件树收进触摸抽屉。
  • 同一路由与认证。
  • Web App Manifest；可安装 PWA 仍在规划中，尚未交付。

Writes are the dangerous part.

写入是最危险的部分。

The server assumes an agent can be wrong, a tab can be stale, and a path can escape. The defaults are built around those failures.

服务端默认假设：Agent 可能出错，标签页可能过期，路径可能逃逸。默认行为围绕这些故障设计。

OAuth 2.1 + PKCE

OAuth 2.1 + PKCE

Authorization-code flow with discovery, dynamic client registration, refresh rotation and revocation. Scoped API keys remain available.

授权码流程，含发现、动态客户端注册、刷新轮换与撤销；同时保留受限 API Key。

Scope and vault allowlist

Scope 与 Vault 白名单

Read, write and files permissions are separate, and every credential is bound to explicit vaults.

read、write、files 权限分离，每个凭据绑定明确的 Vault。

Optimistic concurrency

乐观并发

Reads return a SHA-256 revision. Stale writes must fail instead of merging silently.

读取返回 SHA-256 revision；过期写入必须失败，而不是静默合并。

Path containment

路径约束

Traversal and symlink escapes are rejected, root deletion is refused, and writes are atomic.

拒绝路径穿越与符号链接逃逸，拒绝删除根目录，写入原子化。

Versions, trash, journal

版本、回收站、Journal

Pre-write versions and recoverable trash live outside the vault; multi-note plans are journaled.

写入前版本与可恢复回收站放在 Vault 外；多笔记计划写入 journal。

Secret-free audit

不含秘密值的审计

Audit records the actor, credential type, source and outcome — never the credential itself.

审计记录操作者、凭据类型、来源和结果，绝不记录凭据本身。

Read-only mode

只读模式

One switch stops all vault writes while health, search and reads keep working.

一个开关停止所有 Vault 写入，健康检查、搜索和读取继续工作。

Bounded inputs

有界输入

Read, transfer, archive and search limits are explicit; unsupported Base expressions fail closed.

读取、传输、归档与搜索都有显式上限；不支持的 Base 表达式直接拒绝。
